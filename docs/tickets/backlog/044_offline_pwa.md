# 044 — Offline PWA

## Goal
Upgrade the service worker to a proper Workbox-based implementation so the app shell loads offline, recently-viewed articles and notes are readable without internet, and pending writes queue for sync when connectivity resumes.

## Background
The current service worker is minimal (likely just registers for PWA purposes). This ticket makes the app genuinely useful offline — users can read their saved content on a plane or in an area with no signal.

## Implementation Notes

### Service Worker: Workbox

Replace the current minimal SW with a Workbox-powered implementation (`next-pwa` or a custom `service-worker.ts` compiled separately):

**Caching strategies:**
- **Cache-first**: JS/CSS/font assets (Next.js `/_next/static/**`)
- **Stale-while-revalidate**: images, icons (`/icons/**`, `/_next/image/**`)
- **Network-first with cache fallback**: page HTML and API routes — serve cached version if network fails

Use `workbox-strategies`, `workbox-routing`, `workbox-precaching` from the Workbox npm packages, or use `next-pwa` (wraps Workbox for Next.js).

### IndexedDB: Offline Content Cache

Use `idb-keyval` (lightweight IDB wrapper, ~600B) to cache the last-loaded list data:

- **Articles list**: cache the last fetched articles array under key `articles:<instanceId>`
- **Notes list**: cache under `notes:<instanceId>`
- On page load, if the network fetch fails (or while it is in flight), read from the IDB cache and render immediately
- After a successful network fetch, update the IDB cache

Implementation in client components:
```ts
import { get, set } from 'idb-keyval'

// On load
const cached = await get(`articles:${instanceId}`)
if (cached) setArticles(cached)

// After fetch
const fresh = await fetchArticles()
setArticles(fresh)
await set(`articles:${instanceId}`, fresh)
```

### Offline Banner

A `useOnlineStatus` hook (`src/hooks/use-online-status.ts`) using `window.addEventListener('online'/'offline')`:
- Returns `boolean` — `true` if online
- Used in the app layout to show an "Offline — showing cached content" banner (e.g. a yellow `Alert` strip below the header) when `isOnline === false`
- Banner dismisses automatically when connectivity returns

### Write Queue (Simple, No Conflict Resolution)

When offline, creating a todo or note should not silently fail. Queue pending writes in IDB:

```ts
interface PendingWrite {
  id: string           // local uuid
  type: 'create_todo' | 'create_note'
  payload: unknown
  createdAt: string
}
```

On submit while offline:
1. Save to IDB queue (`pending-writes`)
2. Show the new item in the UI optimistically
3. Show a toast: "Saved offline — will sync when back online"

On connectivity restore (`online` event):
1. Read the pending-writes queue
2. Replay each write via the server action
3. Remove from queue on success; keep on failure (retry next time)
4. Show a toast: "X items synced"

Limit the write queue to `create_todo` and `create_note` for now (the most common actions). Exclude edits and deletes (too complex for simple conflict-free queueing).
